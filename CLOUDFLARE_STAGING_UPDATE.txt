AURUM CLOUDFLARE STAGING UPDATE

This staging package includes the refreshed Sniper UI, a browser-only Deriv read-only session, and the full public Deriv active-market catalogue with selected-only live quote subscriptions. It remains analysis-only; Exness stays PC-local.

Sniper UI
- Selected markets are shown by default; Add markets opens the full search/selection list.
- Selected and live setup views show timeframe, entry, SL, TP1, and clearly labelled data source.
- Sniper remains analysis-only. No trade execution is enabled.

Deriv browser-only read-only session
- Cloudflare staging accepts a Deriv Classic API token with Read scope only (no Trade, Payments, or Admin scopes). The app checks the authorization scopes and fails closed otherwise.
- Authorization is sent directly from the browser tab to Deriv. The token is held in tab session storage and never posted to or stored by the Cloudflare Worker. Hosted `/api/deriv/*` calls and new-API PAT/server sessions are blocked.
- Deriv order proposals, confirmations, buys, closes, and trading automation are blocked in hosted mode. This is account read-only and analysis-only.
- Exness login/restore is hidden and blocked in hosted mode. Exness credentials, symbols, quotes, and candles stay on the PC-local app/bridge; the Worker cannot reach the PC bridge.

Deriv catalogue and selected live feed
- The full active-symbol catalogue is loaded from the public `/api/markets/deriv` endpoint.
- Cloudflare mode disables default all-watchlist tick subscriptions. Click “Follow live” on a Deriv catalogue row to stream that symbol directly from Deriv in this browser; maximum 20 followed markets concurrently.
- Unselected catalogue rows are not streamed. Catalogue availability does not guarantee a current/live quote; the UI reports waiting, live, stale, or unavailable status.
- Exness catalogue rows remain local and have no Cloudflare live feed.

Cloudflare deployment scope
- This archive is a source/build package for the existing cloudflare-staging Worker; it is not a direct browser-upload HTML file.
- Worker API remains separate from Express. It serves read-only signals and public market data; it does not receive broker credentials or account data and does not expose Exness bridge routes.
- No deployment, repository push, production change, database write, or secret change was performed.

Build / verify before any deployment
1. Extract this ZIP, preserving the `aurum/` folder layout.
2. Use Node.js 22, then run `npm ci`, `npm test`, and `npm run build`.
3. Review `CLOUDFLARE_WORKER_MIGRATION.md` and `wrangler.jsonc`.
4. Run a Wrangler dry-run first: `npx --yes wrangler@4.137.0 deploy --dry-run --config wrangler.jsonc`.
5. Deploy only to the `cloudflare-staging` Worker after review and explicit approval. Do not use production credentials/domains.

The archive omits `.git`, node_modules, dist caches, local server/data, logs, bridge_token.txt, and local Python runtime paths. No credentials or broker tokens are included.
