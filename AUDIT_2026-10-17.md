## CRITICAL

### C1 — App-ID digits-only regression (forbidden check reintroduced)
- **Where:** `server/app.js` → `POST /api/deriv/connect`: `if (!/^\d{1,10}$/.test(appId))`
- **Why critical:** Binding rule: *"App ID copied EXACTLY (never reintroduce a
  digits-only check)"* — master prompt §2.8. Any App ID containing a letter is
  rejected server-side before login is even attempted.
- **Fix:** relax to `/^[A-Za-z0-9._~-]{1,64}$/` + honest message ("paste it
  exactly — it may contain letters"). Status: **FIXED ✓**

### C2 — Bridge executes orders with NO per-connection authentication
- **Where:** `bridge/mt5_bridge.py` `handler()` dispatcher (≈line 303):
  `HANDLERS = {login, order, close, positions, quote, search}` — every message
  is dispatched with **no check that `login` succeeded on that socket**.
  `mt5.login()` attaches the terminal **process-globally**, so after one legit
  login, ANY later socket can call `order`/`close`/`positions` unauthenticated.
  Applies to BOTH ports (8787 websockets + 8788 hand-rolled `_ws_loop`).
- **Attack:** any webpage can open `ws://127.0.0.1:8787` from the user's
  browser (WebSocket is not subject to CORS; Origin header is sent but never
  checked). The IP check (`remote[0] not in 127.0.0.1`) does not help — the
  browser itself is local. Result: drive-by page can read account/positions and
  **place or close real trades** once the user has logged in normally.
- **Fix:** (a) per-socket `authed` gate — `order/close/positions/quote/search`
  require a successful `login` on that connection (`auth_required` otherwise);
  (b) Origin check on both upgrade paths — reject browser origins that are not
  127.0.0.1/localhost; (c) optional `AURUM_BRIDGE_TOKEN` env becomes a real
  shared secret when set. Status: **FIXED ✓**

### C3 — Silent min-lot clamp-up: "$1" can silently become full min-lot exposure
- **Where:** `mt5_bridge.py` `usd_to_lots()`: `lots = max(vmin, min(vmax, …))`
  clamps UP to broker minimum with no signal; `handle_order` reply
  (`filled`) returns `lots/price/ticket` only — no requested-vs-actual exposure.
- **Why critical:** US30 min lot is typically **0.1 ≈ $4,000–5,000 notional**.
  The pending acceptance test is a **$1 US30 order** — it would silently open
  min-lot exposure while the UI says "$1". Violates "never invent fills /
  stake = notional exposure" honesty; user's risk math (SL loss) is computed
  for $1, actual position is ~4,600× larger in notional terms.
- **Fix:** order + quote replies now carry `volume_min, contract_size,
  requested_usd, lots, effective_notional, clamped_min`; client warns in the
  filled toast (and confirm flow) with the real numbers. Status: **FIXED ✓**

## HIGH

### H1 — Remember-me note claims "encrypted backup"; it is plain text
- **Where:** `index.html` line 577 (#rememberNote title): "keeps an **encrypted**
  backup of your token" — actual storage: `localStorage['aurum_pat_bk']`, plain
  string (verified `src/main.js` patStore).
- **Why:** honesty rule (§24: disclose plainly). The remember-me tier itself
  STAYS (standing user instruction).
- **Fix:** wording → "plain-text backup… anyone with this browser profile can
  read it". Status: **FIXED ✓**

### H2 — Rate limits keyed behind Railway proxy (all clients share one bucket)
- **Where:** `server/lib/limits.js` keys on `req.ip`; `server/app.js` never sets
  `trust proxy` → behind Railway's LB every client shares the proxy IP: one
  busy visitor can exhaust the single-user budget; logs misattribute IPs.
- **Fix:** `app.set('trust proxy', 1)` (one trusted hop = Railway). Status: **FIXED ✓**

### H3 — No server-side duplicate-order guard on the classic/PAT order route
- **Where:** `server/app.js` `/api/deriv/order` — only client button-disable
  protects against double-submit; a retry/double-click can double-buy. (The
  env-token proxy confirm route is safe: tickets are single-use.)
- **Fix (final design):** opt-in idempotency — the client sends a fresh `once`
  intent key per order (manual HFM gate, manual Deriv order, both sniper
  gates); the SAME key twice inside 60 s → 409 `duplicate_request`. Bodies
  without a key pass untouched, so deliberate rapid repeat orders and the
  risk-limit tests are never blocked (first attempt blocked them — caught by
  the suite and redesigned). Wired on `/api/deriv/order` + all three gates.
  Status: **FIXED ✓ (2 unit tests)**

## MEDIUM

### M1 — Bridge 8788 answers `Access-Control-Allow-Origin: *` on local HTTP
- **Where:** `mt5_bridge.py` (≈497, 433). Any website may read proxied
  `/api/*` responses via the user's own loopback where Private Network Access
  doesn't block it. Fix: echo Origin only for localhost origins, else omit.
  Status: **FIXED ✓**

### M2 — Client fetches have no timeout
- **Where:** `src/main.js` `api()` — zero AbortController usage; a hung scan
  leaves "Scanning…" forever. Fix: optional `timeoutMs` (AbortSignal.timeout),
  applied to scan/backtest/history calls. Status: **FIXED ✓**
